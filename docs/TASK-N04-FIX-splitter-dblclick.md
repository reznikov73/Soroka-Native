# TASK-N04-FIX — двойной клик по сплиттеру сбрасывает веса

Дата: 2026-11-22. Версия: 0.3.16. Дефект найден при разборе чек-листа
приёмки Фазы 2 (`_probe/next/phase2-acceptance.md`, пункт про сплиттеры):
TASK-N04 обещает «двойной клик по сплиттеру возвращает весам пары
дефолт», обработчик `WM_LBUTTONDBLCLK` в `splitter_proc` есть
(`src/ui.rs:531`), но на живой мыши сообщение не приходит ни разу.

## Причина

Класс сплиттера регистрировался без `CS_DBLCLKS` (`src/ui.rs:323`):
`style: CS_HREDRAW | CS_VREDRAW`. Windows в таком классе не синтезирует
`WM_LBUTTONDBLCLK` — второй клик приходит обычным `WM_LBUTTONDOWN`, и
обработчик сброса не выполняется никогда.

Почему это не поймали раньше: в TASK-N04 проверяли синтетическим
`WM_LBUTTONDBLCLK` (посылка сообщения напрямую), а такой тест проходит и
на классе без `CS_DBLCLKS` — проверяет обработчик, но не регистрацию.
Ровно тот случай, когда «зелёная» авто-проверка маскирует дефект.

## Решение

Одна строка: `style: CS_HREDRAW | CS_VREDRAW | CS_DBLCLKS` с комментарием,
почему флаг обязателен. Логика сброса весов не менялась.

## Сделано

- [x] `src/ui.rs`: `CS_DBLCLKS` в регистрации класса сплиттера.
- [x] Версия 0.3.16.
- [x] Проверочный стенд `_probe/n04-dblclick.ps1`: живая мышь — drag
      сплиттера, затем двойной клик; читает `layout.json` до/после.

## Проверено (живой прогон, изолированный APPDATA)

Стенд: отдельный `APPDATA` (`_probe\n03\appdata`), фиктивный ящик, окно
поднято на передний план, `mouse_event` (реальная мышь, не SendMessage).

| Шаг | `weights` в `layout.json` |
|---|---|
| старт без файла | дефолты в памяти (0.2827 / 1.2443 / 2.023) |
| drag сплиттера «дерево\|список» на +60 px | `folders 0.3321, list 1.1949` (сумма пары сохранена) |
| двойной клик по сплиттеру (после drag — по новой позиции) | `folders 0.2827, list 1.2443` — сброс сработал |
| процесс после жестов | жив, раскладка пересчитана |

До правки тот же стенд давал «после dblclick» без изменений — то есть
проверка различает состояние до/после, а не просто «зеленеет».

Замечание по стенду: после drag сплиттер уезжает, поэтому его позицию
надо перечитывать перед двойным кликом — первая версия скрипта кликала
по старой координате (в список) и «подтверждала» дефект.
