# TASK-N07 — Фаза 2, срез 6: трей и автопроверка

Дата: 2026-11-18. Версия: 0.3.6. Предыдущая задача: TASK-N09
(v0.3.5 — настройки, общий settings.json).

## Постановка

ROADMAP N07: иконка в трее, минимизация в трей, автопроверка новых писем
по таймеру (интервал из настроек; IMAP IDLE — отдельно, если решим),
уведомление о новых письмах, счётчик непрочитанных. Критерий приёмки:
письмо приходит — трей/уведомление показывают; окно открывается из трея.

Разделение труда (PLAN-ZAI): z.ai — код среза и кросс-проверка
(cargo check/clippy/test --no-run --target x86_64-pc-windows-gnu);
AutoClaw — живой цикл MSVC (build --release / test / clippy, смоук-тесты)
и запись результата в «Проверено».

## Решения

### Иконки (src/icons/, src/ico.rs)

- Из Soroka `src-tauri/icons/`: `tray.png` и `tray-alert-1.png`
  (TASK-079: конверт и конверт с точкой непрочитанных, 32×32 RGBA)
  сконвертированы в многокадровые .ico (16/20/24/32 — панель задач при
  100–200% DPI); `icon.ico` Сороки взят как есть (7 кадров 16–256) —
  иконка окна/панели задач (раньше оставалась системная заглушка).
  Конвертация PIL `save(sizes=[…])`, записи PNG-сжатые — их понимает
  `CreateIconFromResourceEx` (Vista+).
- Разбор .ico — чистый модуль `src/ico.rs` (ICONDIR, одиночные байты
  ширины/высоты — 0 означает 256, проверка границ кадров) + выбор лучшего
  кадра под размер (точный, иначе ближайший крупнее — даунскейл чище
  апскейла). Тесты на реальных файлах среза и синтетике.
- `CreateIconFromResourceEx(frame, fIcon=true, 0x00030000, cx, cy)` —
  третий параметр `dwver` обязателен (в windows 0.62 сигнатура
  `(&[u8], bool, u32, i32, i32, IMAGE_FLAGS)`); размер —
  `GetSystemMetrics(SM_CXSMICON)` на момент старта (DPI-пересъём иконки
  при переезде между мониторами — при необходимости в N10).

### Иконка трея (src/tray.rs)

- `Shell_NotifyIconW` (в 0.62: `NOTIFYICONDATAW` — без подчёркивания
  перед W, возврат BOOL): NIM_ADD при старте до ShowWindow, NIM_DELETE
  в WM_DESTROY, NIM_MODIFY для подписи/иконки/balloon. Калбэк —
  `WM_APP_TRAY = WM_APP_ATTACH_CLICK + 1` (цепочка WM_APP сохранена).
- Подпись и иконка по общему числу непрочитанных всех ящиков (порт
  set_tray_unread: «POS Mail — N непрочитанных…», иконка с точкой при
  N > 0). Пересчёт — из кэша SQLite (`unread_counts("id::%")` по каждому
  ящику), чтение только в UI по малому запросу — как rebuild_tree.
- Меню правой кнопки: Открыть POS Mail / Проверить почту / Выход —
  порт меню TASK-037 без «Свернуть в трей» (сворачивают «—» и крестик).
  `TrackPopupMenuEx` с `TPM_RETURNCMD` (в 0.62 возвращает BOOL — значение
  команды в `.0`), выбор уходит в главное окно постом `WM_COMMAND`
  (lparam=0) — тот же путь, что у главного меню; `IDM_TRAY_OPEN=140`
  добавлен к IDM в ui.rs, «Проверить» = IDM_SYNC, «Выход» = IDM_EXIT.
  SetForegroundWindow до и WM_NULL после — классика KB135788 от
  исчезающего меню.
- Клик левой / двойной / NIN_BALLOONUSERCLICK → показать окно
  (SW_RESTORE из свёрнутого + SetForegroundWindow).
- TaskbarCreated (`RegisterWindowMessageW`): Explorer перезапустился —
  иконка добавляется заново (в default-ветке wndproc).

### Сворачивание в трей (порт TASK-040/072 Soroka)

- Кнопка «—»: WM_SIZE + SIZE_MINIMIZED → `ShowWindow(SW_HIDE)` при
  включённом `ui.minimize_to_tray` (в Soroka — обработчик #win-min).
- Крестик: WM_CLOSE при включённом флаге прячет окно, не завершает
  программу (TASK-072), выход — меню трея; подсказка
  «POS Mail свёрнут в трей. Выход — в меню трея.» — balloon один раз
  за запуск (в Soroka showToast при каждом сворачивании, но он в скрытом
  окне не виден; balloon заметнее — решили не спамить).
- Флаг кэшируется в AppState (не перечитываем settings.json на каждый
  WM_CLOSE), обновляется при WM_APP_SETTINGS_SAVED.

### Автопроверка (таймер)

- `SetTimer(IDT_AUTOSYNC)` с интервалом `native_autosync_min` минут
  (0 — KillTimer; максимум 1440 из настроек N09). Таймер живёт, пока
  жив цикл сообщений, — работает и со скрытым окном.
- Тик → синхронизация INBOX **каждого** ящика (у Soroka таймеры на
  каждый ящик `check_interval_sec`; интервал у нас один общий — ключ
  из настроек N09). Задачи — те же Job::SyncFolder, что у F5; очередь
  рабочего потока сериализует их, IMAP-соединения не конфликтуют.
- Перевооружение при WM_APP_SETTINGS_SAVED.

### Уведомления о новых письмах (порт TASK-087/099)

- Гварды как в Soroka: `ui.notifications` включены и главное окно не
  на виду (IsWindowVisible && GetForegroundWindow — порт
  «is_visible && is_focused»).
- **Число «новых» — честное**: перед INBOX-синхронизацией (F5, меню
  трея, автотаймер) снимаем UID из кэша, после SyncDone сравниваем
  со свежим. В Soroka в notify_new_mail уходит `fetched` — счётчик
  ВСЕХ загруженных заголовков (до 200), т.е. фоновая проверка в трее
  каждый раз сообщала бы «200 новых писем». Отклонение от дословного
  порта записано здесь сознательно.
- Базлайны: стартовая синхронизация снимок не делает (иначе каждый
  запуск = «все письма новые»); пустой кэш нового ящика тоже не
  снимается — первая проверка устанавливает базу без уведомления.
- Тексты (src/notify.rs): заголовок склоняется правильно
  («Новое письмо», «2 новых письма», «5 новых писем», «21 новое
  письмо») — в Soroka для любого числа писалось «новых письма»;
  тело — «От кого: Тема» или «Проверьте почту в POS Mail».
- Balloon: `NIIF_INFO | NIIF_RESPECT_QUIET_TIME` (режим «не беспокоить»
  не прорывается), uTimeout 10000.

### Автозапуск (src/autostart.rs)

- `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение
  `SorokaNative` = «путь\к\POSmail.exe» в кавычках. Имя отличается от
  ярлыка Soroka (tauri-plugin-autostart) — не конфликтуют, флаг
  `ui.autostart` при этом общий из settings.json.
- Включено — RegSetValueExW (REG_SZ, UTF-16 байты с NUL), выключено —
  RegDeleteValueW (отсутствующее значение = успех). Синхронизация при
  старте и при сохранении настроек. В 0.62 все Reg* возвращают
  WIN32_ERROR; RegOpenKeyExW принимает `*mut HKEY` пятым аргументом.

### Инфраструктура песочницы (не код среза — запись для истории)

В середине среза песочница пережила чистку: исчезли `soroka-native/.git`
и всё дерево (восстановлено клоном с GitHub — HEAD совпадал с fb17160),
содержимое `soroka-ref`, `~/.cargo`, `~/.rustup` и target/. После этого:
rustup переустановлен; для кросс-сборки вместо mingw-gcc собрана связка
zig cc 0.14.1 (шим `x86_64-w64-mingw32-gcc`, тройка переписывается на
`x86_64-windows-gnu` — вариант с `pc` zig не принимает) + rust-lld как
линковщик + шим `x86_64-w64-mingw32-dlltool` → lld-link `/DEF:/OUT:`
(raw-dylib у windows-крейтов; llvm-dlltool в llvm-tools больше не
поставляется) + импорт-библиотеки mingw-w64 из deb-пакетов (apt-get
download без root) + `-C link-self-contained=yes` (crt2.o).
Рабочий кэш — `/tmp/sn-target` (CARGO_TARGET_DIR), чтобы не раздувать
каталог проекта: чистильщик песочницы снимает большие каталоги.

## Осталось

  отдельно, если потребуется).
- Бейджи непрочитанных в дереве папок — не в этом срезе (UX-начинка,

- Balloon про «свёрнут в трей» показывается один раз за запуск; если
  владельцу захочется как в Soroka (каждый раз) — поменять флаг.
