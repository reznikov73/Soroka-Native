# TASK-N10 — Фаза 2, срез 8: UX до релиза Фазы 2

Дата: 2026-11-19. Версия: 0.3.9 (нумерация PLAN-ZAI после фикса
мерцания: v0.3.7 — AutoClaw, N08 = v0.3.8, N10 = v0.3.9). Предыдущая
задача: TASK-N08 (v0.3.8 — черновики).

## Постановка

ROADMAP N10: маркер «совпало в теле» в строках поиска (сейчас — только
счётчик в статусе); контекстные меню списка/дерева (сверить с Soroka);
перетаскивание вложений из шапки письма; сверить мелкую UX-начинку с
Soroka. Критерий приёмки: ежедневные операции выполняются без походов
в меню; дальше — неделя ежедневного использования вместо Soroka
(критерий Фазы 2).

Разделение труда (PLAN-ZAI): z.ai — код среза и кросс-проверка
(cargo check/clippy/test --no-run --target x86_64-pc-windows-gnu);
AutoClaw — живой цикл MSVC и запись результата в «Проверено».

## Решения

### Маркер «совпало в теле» (ui.rs)

- Сорока помечает такие строки классом body-hit и отдельной группой
  «В тексте письма · N» (поиск по папке); в глобальном поиске метки нет.
  У нас поиск сразу по всем папкам ящика — маркер ушёл в колонку
  «Папка»: суффикс «· в теле» у строк, где in_body=true (флаг из
  SearchHit ядра, TASK-082). Чистая функция folder_cell(name, body_hit).
- Счётчик в статусе остался (дублирование сознательное — статус
  подводит итог, маркер работает по строке).

### Контекстные меню (ui.rs + main.rs WM_CONTEXTMENU)

- Список (порт openMsgMenu Сороки): правый клик сначала выделяет строку
  под курсором (LVM_HITTEST + LVM_SETITEMSTATE — как Проводник; в
  Soroka каждое действие само вызывало selectMessage) — LVN_ITEMCHANGED
  открывает письмо, команды меню работают с selected_uid. Состав:
  Ответить / Ответить всем / Переслать / — / Прочитано-Непрочитано
  (подпись склоняется по состоянию строки, как в Сороке) / В корзину.
  Отличие от Сороки: у неё только Открыть/Корзина/Спам/Прочитано —
  ответ/пересылка добавлены (команды главного меню уже существовали,
  ради них срез и затевался — «ежедневные операции без походов в меню»);
  спам-пункта нет — спама в оболочке нет. Открыть не нужен — правый клик
  уже выделил и открыл письмо.
- Дерево (у Сороки меню дерева нет — добавлено по PLAN-ZAI):
  на папке — «Проверить папку»; правый клик выбирает узел
  (TVM_HITTEST/TVHT_ONITEM → TVM_SELECTITEM), синхронизируется уже она.
  На заголовке ящика меню нет.
- Реализация — TrackPopupMenuEx c TPM_RETURNCMD, выбор уходит постом
  WM_COMMAND (lparam=0) — тот же путь, что у главного меню и трея;
  SetForegroundWindow + WM_NULL (KB135788). Меню не плодит новых
  команд — только существующие IDM_*.
- WM_CONTEXTMENU: координаты из lparam (знаковые, многомонитор), -1 —
  с клавиатуры (берём курсор); прочие цели — DefWindowProc (меню окна
  у заголовка не ломаем).

### Выделение строк палитрой (ui.rs, theme.rs)

- Сорока: .m-row.selected — фон --accent-weak-2 (тёмная тема
  rgba(139,131,255,.24) поверх bg-app) + акцентная полоса слева.
  В custom draw строки теперь при CDIS_SELECTED ставится clrTextBk =
  p.selected (accent-weak-2, сведён к сплошному цвету: тёмная
  #373659, светлая #DFDEF6 из светлой секции styles.css) и clrText =
  p.text — вместо системного синего с белым. Акцентную полосу слева
  GDI-строкой ListView не повторить — отличие записано сознательно.

### Рамка поля поиска (main.rs, ui.rs)

- WS_EX_CLIENTEDGE оставлен (он бронирует 2px под рамку), но WM_NCPAINT
  в сабклассе поля рисует плоскую рамку палитрой: --stroke обычно,
  --accent в фокусе (как .tb-search в Soroka), FrameRect ×2. Смена
  фокуса (WM_SETFOCUS/WM_KILLFOCUS) и темы (apply_theme шлёт полю
  WM_NCPAINT — InvalidateRect невидимую область не трогает)
  перекрашивают рамку.

### Перетаскивание вложений — НЕ перенесено (сознательно)

- В Сороке drag-out вложений нет (в main.ts нет dragstart/draggable —
  только клик = сохранение в «Загрузки»; TASK-086 добавлял EML/зум,
  не drag). «Сверить с Soroka» — паритета нет, добавлять поверх
  означало бы новый функционал: жест из WebView2 (HTML5-drag без
  File в странице не стартует) + COM IDataObject/IDropSource +
  DoDragDrop с CF_HDROP — отдельный срез по решению владельца.
  Клик-сохранение осталось как было.

## Осталось

- Drag-out вложений из шапки письма — не в срезе (в Soroka его нет;
  нужен COM IDropSource/IDataObject + жест из WebView2 — отдельная
  задача по решению владельца).
- Акцентная полоса слева у выделенной строки (как box-shadow в Сороке)
  — GDI-строка ListView это не умеет; если владельцу важно — owner-draw
  всей строки (CDRF_SKIPDEFAULT + свой DrawText) отдельно.
- Меню дерева минимально («Проверить папку»); бейджи непрочитанных в
  дереве — вместе с Фазой 3 (как в Soroka TASK-068/badges).
- Дальше по PLAN-ZAI: срезы Фазы 2 собраны (N05–N10) — живая приёмка
  владельцем, неделя ежедневной работы вместо Soroka, затем решение
  о Фазе 3 (N11 календарь → N12 контакты → N13/N14 GigaChat).
