# PLAN-ZAI — план работы для z.ai (срезы N09 → N10)

Дата: 2026-11-18. Для: z.ai (GLM 5.3). База: v0.3.4 + живая проверка
AutoClaw (см. «Проверено» в TASK-N05/N06). Следующий срез — N09.

## Разделение труда (как работаем)

- **z.ai**: код среза по TASK-документу (Постановка/Решения/Сделано),
  проверка кросс-сборкой `cargo check/clippy/test --no-run
  --target x86_64-pc-windows-gnu`, коммит по формату WORKFLOW
  (`feat: v0.3.5 — ... (TASK-N09)`), push в main.
- **AutoClaw (машина владельца, MSVC)**: pull, live-цикл
  build --release / test / clippy, смоук-тесты (запуск, синтетические
  сообщения, layout.json), результат — в «Проверено» TASK-документа,
  push. Правки MSVC-специфики — минимальные, с записью в build-log.
- **Один срез — один коммит — один TASK-документ.** Следующий срез
  начинать после живой проверки предыдущего. Версии: N09 = v0.3.5,
  N07 = v0.3.6, N08 = v0.3.7, N10 = v0.3.8.
- Перед стартом перечитать: ROADMAP.md (критерии срезов), WORKFLOW.md,
  TASK-N05/N06 (свежие решения: единый layout.json, палитры).

## N09 Настройки (v0.3.5) — следующий срез

**Эталон**: `Soroka/src-tauri/src/settings.rs` (~460 строк) — переносить
как есть (это ядро, не src/mail/, но правило то же: дословно). Файл:
`%APPDATA%\Soroka\settings.json` — **общий с Soroka**, Soroka продолжает
его читать и писать.

**Структура Settings (уже в Soroka):** `categories` (AI-категории писем,
TASK-068), `prompts`, `signatures`/`account_signatures` (TASK-030),
`appearance` (transparent/dense_list/show_badge/...), `ui: UiSettings`
(minimize_to_tray=true, autostart=false, delayed_actions=false,
idle_enabled=false, notifications=true).

**Что делать:**
1. `src/settings.rs` — порт settings.rs Soroka дословно (serde уже есть).
2. Чтение при старте; **запись — только read-modify-write** прочитанного
   файла (меняем только изменённые нами поля, остальное сохраняем как
   прочитано) — Soroka параллельно живёт в этом файле. Не переписывать
   файл своей моделью!
3. Диалог настроек (Win32, как account_dlg): тема (тёмная/светлая —
   наша, живёт здесь, из layout.json переезжает в settings.json в свой
   ключ, например `native_theme` — serde unknown fields Soroka
   игнорирует, схема не ломается), minimize_to_tray, notifications,
   autostart, интервал автопроверки (наш ключ, для N07), ключ GigaChat.
4. Ключ GigaChat: в Soroka он в env `SOROKA_GIGACHAT_KEY` или
   `%APPDATA%\Soroka\gigachat.json`; в диалоге — показать/изменить,
   писать в gigachat.json (read-modify-write). Пятиться от DPAPI не
   нужно — Soroka хранит ключ открыто.
5. Тема: layout.json оставляет веса и геометрию; theme уезжает в
   settings.json. Старые layout.json с полем theme — читать, но
   приоритет у settings.json (миграция: если в layout.json тема была
   переопределена и settings.json ключа нет — перенести однажды).
6. Cargo: v0.3.5. Проверка: кросс-gnu; живой цикл — AutoClaw.

**Критерий приёмки:** настройки читаются из общего settings.json Soroka
(у владельца он существует!), диалог меняет, перезапуск сохраняет,
Soroka после наших записей работает.

**Критерий:** письмо на тестовый ящик — трей/уведомление сработали;

## Замечания по среде (от AutoClaw, из живых сборок)

- Сигнатуры windows 0.62, которые уже проверены живьём: SetCapture/
  ReleaseCapture/TrackMouseEvent/TRACKMOUSEEVENT/TME_LEAVE — в
  `Win32::UI::Input::KeyboardAndMouse` (НЕ в WindowsAndMessaging);
  WM_MOUSELEAVE — в `Win32::UI::Controls`; CreateAcceleratorTableW
  требует выравнивание буфера ≥4 байта (у нас AccelTable align(8) —
  не трогать).
- clippy -D warnings строг: не оставлять match-ловушек (неконстантный
  паттерн глотает ветки), вложенных unsafe, collapsible_if — let-chains
  разрешены (edition 2024).
- layout.json: формат зафиксирован (Layout: wf/wl/wr, dark→theme
  уедет в N09, main/compose/account) — AutoClaw гоняет по нему
  синтетические тесты; менять формат только в TASK-документе с
  пометкой для AutoClaw.
