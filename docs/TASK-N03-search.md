# TASK-N03 — Фаза 2, срез 1: поиск FTS5 в нативной оболочке

Дата: 2026-11-18. Версия: 0.3.0. Предыдущая задача: TASK-N02
(v0.2.4 — живая проверка Фазы 1 прошла, ресайз 8,7 мс/шаг).

## Постановка

Первый срез Фазы 2 (паритет ядра): поиск писем, как в Soroka —
TASK-033 (поиск по всем папкам ящика), TASK-036 (пометка «совпало в теле»),
TASK-082 (FTS5-индекс в SQLite). Ядро уже умеет всё это
(`store.rs::search_messages`, перенесено дословно), оболочке нужна проводка:
поле ввода, запуск запроса, выдача в виртуальный список, возврат к папке.
Схема окна не меняется: список остаётся виртуальным, DOM в кадре ресайза
по-прежнему нет.

## Решения

### UX (повторяет Soroka, где это дёшево)

- **Вызов**: клавиша `/` (как TASK-080 в Soroka; VK_OEM_2 не зависит от
  раскладки — на русской раскладке та же физическая клавиша) или
  `Папка → Найти в ящике...`. Повторная `/` — просто фокус на поле.
- **Поле**: скрытая строка EDIT над списком (30 px), подсказка
  (EM_SETCUEBANNER) «Поиск по всем папкам ящика — Enter: искать, Esc: к
  папке». Появляется по `/`, исчезает при закрытии.
- **Живой поиск**: ввод → EN_CHANGE → таймер 300 мс (debounce, как в
  Soroka) → запрос в бэкенд. Enter — сразу, предварительно убив таймер.
- **Esc**: закрыть поиск, вернуть список к текущей папке. Пустой запрос
  при запуске = то же самое (предсказуемо). Esc работает и из списка, и
  из поля; когда поиск не открыт — ничего не делает.
- **Выдача**: тот же виртуальный список, но 5 колонок — добавлена
  «Папка». Сортировка — новые сверху (rowid DESC, как в SQL ядра).
- **Клик по строке выдачи**: письмо открывается в панели, а его папка
  становится текущим контекстом — ответ/удаление/флаги/вложения работают
  сразу, без выхода из поиска. Это осознанное упрощение против Soroka
  (там письмо открывалось поверх выдачи без смены контекста): все пути
  Фазы 1 (FetchBody/SetSeen/Delete по ключу папки) работают без правок.
- **Статус**: «поиск «q»: N писем, M совпало в теле — Esc к папке».

### Данные

- `Job::Search { account_id, query }` в рабочий поток →
  `store.search_messages(account_id, None, query, 200)` (лимит 200 — как
  у команды Soroka) → `MailEvent::SearchDone { query, hits }`.
  `query` — эхо: UI отбрасывает устаревшие выдачи (набор продолжается).
- Ящик поиска — текущий выбранный (`current_account`), при отсутствии —
  первый из accounts.json. Поиск идёт по всем папкам ящика (folder=None),
  FTS5-индекс уже наполнен синхронизациями (TASK-082 в ядре).
- `state.rs`: `ListRow { hdr: MessageHeader, folder: Option<String> }` —
  строки списка теперь несут папку (в режиме папки folder = None).
  Единый вектор вместо параллельных массивов — меньше шансов рассинхрона.
  `search_query: Option<String>` — режим поиска; `hwnd_search` — поле.

### Оболочка

- `ui.rs`: `set_list_columns(hwnd, search)` — переключение 4/5 колонок
  (LVM_DELETECOLUMN ×N + вставка; расширенные стили списка сохраняются);
  `enter_search` / `exit_search` / `fire_search`; выдача `SearchDone`
  собирается в `ListRow` (поля ядра, недоступные из поиска — to/cc/msg_id/
  thread_key — пустые: для строки списка они не нужны; цитата ответа
  берётся из pane_body, не из заголовка).
- `main.rs`: создание EDIT + сабкласс (GWLP_WNDPROC; исходная процедура —
  в GWLP_USERDATA): Enter/Esc уходят WM_COMMAND главному окну, WM_CHAR
  для них гасится (чтобы EDIT не пищал). Раскладка: поле — полоса над
  списком, список сдвигается на SEARCH_H. WM_TIMER — debounce. EN_CHANGE
  в WM_COMMAND маршрутизируется до менюшной ветки (lparam ≠ 0).
- **Ускорители теперь привязаны к фокусу** (баг Фазы 1 заодно закрыт):
  TranslateAccelerator вызывается, только когда фокус в главном окне.
  В поле поиска буквы и «/» печатаются, а не срабатывают как команды;
  в окнах редактора Ctrl+R больше не открывает второе окно ответа
  поверх набираемого письма. Фокус внутри WebView2 живёт в другом потоке
  (GetFocus пуст) — там ускорители работают как раньше.
- Синхронизация во время поиска не затирает выдачу: `SyncDone` и
  `rebuild_tree_keep` обновляют список только вне режима поиска
  (статус обновляется всегда). Выбор папки в дереве закрывает поиск.

## Проверено

- Сигнатуры всех новых вызовов сверены с исходниками `windows-0.62.0`
  (скачаны crates.io, тот же крейт, что линкует wry 0.57):
  `SetTimer(Option<HWND>, usize, u32, TIMERPROC) -> usize`,
  `KillTimer(Option<HWND>, usize) -> Result<()>`,
  `GetParent(HWND) -> Result<HWND>` (в коде — `unwrap_or_default`),
  `GetAncestor(HWND, GET_ANCESTOR_FLAGS) -> HWND` (без Result),
  `GetFocus() -> HWND`, `SetWindowLongPtrW(HWND, _, isize) -> isize`,
  `CallWindowProcW(WNDPROC, ...)`, `TIMERPROC`/`WNDPROC` = `Option<fn>`;
  `ES_AUTOHSCROLL` (i32) и `EN_CHANGE` лежат в `WindowsAndMessaging`
  (не в Controls), `LVM_DELETECOLUMN = 4124 (0x100C)` — импортирован из
  крейта, `EM_SETCUEBANNER/EM_SETSEL` — локальные константы с верными
  значениями (5377/177). Транзитивно верно и для `VK_RETURN/VK_ESCAPE`
  (`VIRTUAL_KEY(u16)`).
- Сборка/тесты/clippy — на машине владельца (AutoClaw 2.4.0): код
  писался вне Windows-машины, первая сборка на ней вскрыла 5 мелких
  расхождений (E0609: счётчик непрочитанных — `m.hdr.seen`, не `m.seen`;
  edition-2024 `unsafe {}` вокруг `layout` в wndproc; каст сабкласс-прок
  `as *const () as isize`; лишний импорт `KillTimer`; выравнивание таблицы
  ускорителей — CreateAcceleratorTableW на x64 требует буфер >= 4 байт
  (golang/go#64729), а [ACCEL; _] выровнен на 2, из-за чего запуск
  эпизодически падал с ERROR_NOACCESS 0x800703E6; таблица обёрнута
  в `#[repr(C, align(8))]`). Правки минимальные, каждая записана
  в `docs/build-log.txt`. После правок (v0.3.1): `cargo build --release` —
  чисто, `cargo test` — 55 passed / 0 failed / 1 ignored,
  `cargo clippy --all-targets -- -D warnings` — чисто.

### Чек-лист приёмки (уровень A + T)

1. `/` из списка (в т.ч. на русской раскладке) — поле появилось над
   списком, фокус в нём, подсказка видна; Esc — поле скрылось, список
   вернулся к папке без сдвигов.
2. Ввод слова из темы письма — после паузы ~0,3 с выдача обновилась;
   Enter — сразу; длинный ввод не подвешивает UI (запросы идут в
   рабочий поток, устаревшие отбрасываются).
3. Кириллица и регистр: «ТЕСТ» находит «тест». Адрес находится по
   частям: «ivan» находит ivan@mail.ru. `*`, кавычки, дефисы не ломают
   запрос. Пустой запрос после стирания — возврат к папке.
4. Колонка «Папка» заполнена; клик по строке — письмо открывается,
   Ctrl+R отвечает на него (контекст — папка строки), Del работает.
   Непрочитанные в выдаче — полужирные, после открытия — обычные.
5. Статус: «поиск «q»: N писем, M совпало в теле — Esc к папке».
6. Во время открытого поиска: F5 не затирает выдачу (статус меняется),
   выбор папки в дереве закрывает поиск и показывает папку.
7. Регресс Фазы 1: Ctrl+R/Ctrl+N из списка работают; в окне написания
   Ctrl+R больше не открывает второе окно ответа (проверить именно это);
   буквы в поле поиска печатаются, включая «/»; клик в тело письма
   (WebView2) и затем Ctrl+R — работает.
8. Ресайз с открытым поиском — без лагов.
