# TASK-N08 — Фаза 2, срез 7: черновики

Дата: 2026-11-19. Версия: 0.3.7. Предыдущая задача: TASK-N07
(v0.3.6 — трей и автопроверка).

## Постановка

ROADMAP N08: черновики при написании — локальные + папка Drafts на сервере;
продолжение редактирования; сохранение при закрытии окна написания.
Критерий приёмки: закрыл окно — черновик на месте (на сервере и локально),
продолжил с того же места; отправил — черновик убран.

Эталон — TASK-022 Soroka (кнопка «В черновики» + индикатор «✓ сохранено
ЧЧ:ММ», автосохранение 20 с без пересохранения неизменённого, APPEND с
флагом \Draft и заголовком X-Soroka-Draft, двойной клик открывает редактор,
после отправки черновик удаляется с сервера и из кэша). Ядро уже всё умело
(TASK-N02 перенёс store.save_draft/load_drafts/draft_by_uid/drop_draft,
imap.append_draft/delete_permanently/find_drafts) — срез только оболочка.

Разделение труда (PLAN-ZAI): z.ai — код среза и кросс-проверка
(cargo check/clippy/test --no-run --target x86_64-pc-windows-gnu);
AutoClaw — живой цикл MSVC и запись результата в «Проверено».

## Решения

### Идентичность и содержимое черновика (src/draft.rs — чистый модуль)

- Идентификатор — на всё время редактирования окна (порт newDraftId):
  `sn-draft-<millis:016x>-<rand:016x>`; случайность — хеш RandomState
  (сид процесса), без внешнего rand-крейта. Токен без пробелов — годится
  в заголовок X-Soroka-Draft.
- Отпечаток изменений (порт lastDraftPayload): JSON [to, cc, subject,
  body, вложения]. У Сороки в отпечатке имена вложений; мы добавили
  размер — замена файла с тем же именем тоже ловится. Не изменилось —
  задача сохранения не ставится (каждое сохранение это IMAP APPEND +
  удаление старой копии).
- Заголовок X-Soroka-Draft вставляется в шапку готового MIME (порт
  insert_draft_header) — по нему append_draft находит UID на серверах
  без UIDPLUS.
- Копия (cc) и вложения — в колонке attachments записи drafts (JSON:
  `{cc, atts:[{name, mime, data_b64}]}`). У DraftRecord Сороки этих
  полей нет (свои записи она пишет с attachments: None), а колонка есть
  — запись остаётся совместимой: Сорока читает её как свою (получатели/
  тема/текст), наш JSON не видит. Битый JSON/base64 у чужой записи —
  читаем как пустые (тест).

### Сохранение (Job::SaveDraft в backend.rs, порт save_draft)

- Сборка MIME — smtp::build_message_full (вложения включаются); пустое
  «Кому» собирается адресом самого ящика, как в Сороке (To: обязателен);
  в локальной записи остаётся пустым.
- Отличие от Сороки (сознательное): недописанный/невалидный адрес не
  роняет сохранение — серверная копия собирается без получателей (они
  живут в локальной записи). У Сороки черновик с недописанным адресом
  вообще не сохранялся и терялся при закрытии.
- Папка \Drafts — find_drafts по кэшу папок, иначе LIST (как в Сороке);
  на сервер уходит имя без префикса ящика.
- APPEND с \Draft (append_draft) → UID из APPENDUID; старая серверная
  копия удаляется (delete_permanently), только когда есть новая — без
  новой старую не трогаем (у Сороки guard слабее: без новой копии она
  всё равно пытается удалить старую).
- Отличие от Сороки (сознательное): сервер/папка недоступны — черновик
  сохраняется локально (uid=None), статус «✓ сохранено локально ЧЧ:ММ
  (причина)»; серверная копия появится при первом успешном сохранении.
  У Сороки ошибка = черновик не сохраняется вовсе.
- Ответ окну редактора — WM_APP_DRAFT_SAVED (Box&lt;DraftSaved&gt;:
  ok, print-эхо, label, msg) — продолжение цепочки WM_APP за треем.

### Окно написания (src/compose.rs)

- Кнопка «В черновики» (IDC_BTN_DRAFT) и «Отмена» → «Закрыть»: закрытие
  теперь сохраняет черновик, а не выбрасывает (порт closeCompose(true)).
- Автосохранение — SetTimer 20 c (IDT_DRAFT_AUTOSAVE, живёт в окне
  редактора; порт startDraftAutosave); KillTimer в WM_DESTROY.
- WM_CLOSE (крестик/«Закрыть»/Alt+F4): пустое и неотредактированное —
  просто закрыть; изменившееся — поставить задачу и закрыться по ответу
  (closing_saving), статус «сохраняю черновик...»; ошибка при закрытии —
  не теряем текст молча: MessageBox «закрыть без сохранения?».
- Отправка в пути — закрываем сразу (черновик уберёт сама отправка);
  save_draft_flow на время отправки не срабатывает (guard st.sending) —
  иначе автотик мог бы пересоздать черновик сразу за отправкой.
- Успех: draft_saved=true, last_print=отпечаток из ответа, статус
  «✓ сохранено ЧЧ:ММ» (порт composeSaved; GetLocalTime в рабочем потоке).
- Пустой черновик не сохраняется (нечего; прежняя серверная копия, если
  была, остаётся в папке — удаляется оттуда как обычное письмо).

### Отправка (backend.rs send_mail + draft_id)

- Job::SendMail несёт Option&lt;draft_id&gt; (Окно передаёт его, только
  если черновик когда-либо сохранялся). После успеха — и прямого, и
  через очередь TASK-089 (как в Сороке: ok = отправлено/в очереди) —
  cleanup_draft: серверная копия (\Deleted + EXPUNGE) и запись в кэше
  (порт delete_draft). Очередь задач FIFO: поставленное раньше
  сохранение выполнится до отправки и будет убрано ею же.

### Продолжение редактирования (main.rs)

- Двойной клик по строке — LVN_ITEMACTIVATE (в оболочке до среза
  двойной клик по списку не обрабатывался вообще). В папке черновиков
  (проверка find_drafts по кэшу — тот же выбор папки, что при сохранении)
  и есть локальная запись с этим UID (draft_by_uid, чтение кэша как в
  rebuild_tree) — окно написания с получателями/копией/текстом/вложениями
  и тем же draft_id: пересохранения заменяют серверную копию, а не
  плодят новые; отпечаток инициализируется содержимым — автосохранение
  не перезаписывает только что открытое.
- Черновики Сороки открываются так же (запись общая; cc/вложения у её
  записей пусты — как у неё самой).
- После закрытия редактора главное окно, стоящее на папке черновиков,
  пересинхронизирует её (порт mail-changed после закрытия compose).
