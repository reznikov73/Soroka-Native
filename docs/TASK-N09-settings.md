# TASK-N09 — Фаза 2, срез 5: настройки (общий settings.json)

Дата: 2026-11-18. Версия: 0.3.5. Предыдущая задача: TASK-N06
(v0.3.4 — геометрия окон).

## Постановка

ROADMAP N09: порт settings Soroka (settings.json общий), диалог настроек:
тема, интервал автопроверки, поведение трея, поле ключа GigaChat (заранее
для N13). Критерий приёмки: настройки читаются из общего settings.json
Soroka, диалог меняет, перезапуск сохраняет, Soroka после наших записей
работает.

Разделение труда (PLAN-ZAI): z.ai — код среза и кросс-проверка
(cargo check/clippy/test --no-run --target x86_64-pc-windows-gnu);
AutoClaw — живой цикл MSVC (build --release / test / clippy, смоук-тесты)
и запись результата в «Проверено».

## Решения

### Порт ядра настроек (src/settings.rs)

- `settings.rs` Soroka (553 строки с тестами) перенесён дословно:
  структуры CategoryRule/Category/Prompts/Signature/AccountSignature/
  Settings/UiSettings/Appearance, `apply()`, `defaults()` (10 категорий
  с правилами 1С/обучения, 4 промпта, основная подпись), методы
  (подписи ящиков, подбор категории, сборка промптов), `load()` с
  заполнением пустых категорий/промптов дефолтами, все 7 тестов Soroka.
  Часть API (категории/промпты/подписи) заработает в Фазе 3 (N13/N14) —
  на модуль `#[allow(dead_code)]`, как у `src/mail/`.
- **`save()` Soroka НЕ переносится**: он переписывает файл всей своей
  моделью, а файл общий — Soroka живёт в нём параллельно. Мы пишем
  только read-modify-write поверх прочитанного файла как `Value`:
  меняются лишь наши ключи, всё остальное (включая неизвестные нам поля)
  сохраняется. Файла нет/битый — базой берётся полный набор дефолтов
  (как если бы Soroka сам создал его при первом сохранении).

### Наши ключи в settings.json

- `native_theme`: «dark» (дефолт, как в Soroka) | «light» — тема
  оболочки, переехала из layout.json. Любое значение кроме «light»
  читается как тёмная.
- `native_autosync_min`: интервал автопроверки, минут, 0 — не
  проверять (дефолт). Таймер — N07; ключ заведён сейчас, как велит
  порядок срезов (настройки раньше трея). Ограничение сверху — 1440.
- `ui.minimize_to_tray` / `ui.notifications` / `ui.autostart` — поля
  UiSettings Soroka (TASK-040/099): поведение общее для обоих клиентов,
  пишем их в существующий раздел `ui`, чужие поля раздела
  (delayed_actions, idle_enabled) сохраняем.
- serde по умолчанию игнорирует неизвестные поля — наши ключи не ломают
  схему Soroka (проверено её же тестами на старых файлах с лишними
  полями).

### Миграция темы из layout.json (одноразовая)

- При старте `settings::init_theme(layout_theme)`: settings.json имеет
  приоритет; если `native_theme` там нет, а старый layout.json хранил
  тему (N05) — значение переносится в settings.json. Нечего переносить
  и файла нет — дефолт (тёмная), файл не создаём.
- **Формат layout.json изменился — важно для AutoClaw**: поле `theme`
  больше не пишется. Старые файлы с `theme` читаются (для миграции);
  любая наша запись (веса при перетаскивании сплиттера, геометрия при
  закрытии окон) вычищает устаревший ключ. Формат теперь:
  `{weights:{folders,list,reading}, main/compose/account}` — тема
  у settings.json. Синтетические тесты AutoClaw по layout.json —
  поправить соответственно.
- `layout_store::save()` лишился параметра темы (3 аргумента);
  `Layout.dark` → `Layout.theme: Option<String>` (сырое значение для
  миграции).

### Диалог настроек (src/settings_dlg.rs, паттерн account_dlg)

- Окно `SorokaSettingsWnd` (не модальное, одно на приложение,
  `st.hwnd_settings`), пункт «Файл → Настройки...».
- Поля: тема (combobox «Тёмная (палитра Soroka)»/«Светлая»), флажки
  «Кнопка «—» прячет окно в трей», «Уведомления Windows о новых
  письмах», «Запускать при входе в Windows», интервал автопроверки
  (минуты, 0–1440), ключ GigaChat + пояснение источника, кнопки
  «Убрать ключ»/«Сохранить»/«Отмена».
- «Сохранить»: `store_native` (RMW settings.json) → сообщение родителю
  WM_APP_SETTINGS_SAVED → главное окно перечитывает ключи; если тема
  сменилась — применяется как «Вид → Тёмная тема» (выделено в
  `set_theme()`, используемую и меню, и диалогом).
- Геометрию окна настроек в layout.json не храним: формат файла
  зафиксирован для синтетических тестов AutoClaw, диалог маленький и
  редкий — системная позиция достаточна (KISS).

### Ключ GigaChat (src/ai/gigachat.rs, Soroka TASK-041)

- Перенесена несетевая часть: `parse_api_key`, `key_path`, env
  `SOROKA_GIGACHAT_KEY`, `load_api_key`, `key_status`, `file_key`
  (для показа в диалоге; env-ключ не отдаём — как в Soroka, TASK-041),
  `save_api_key`, `clear_api_key`. Сетевая часть (токены, запросы,
  AiError) — N13; до тех пор `load_api_key` и поля `KeyStatus` под
  `#[allow(dead_code)]` (паритет API).
- Отличие от Soroka: `save_api_key` пишет gigachat.json
  read-modify-write (у Soroka — перезапись `{"api_key":…}`); проверка
  длины ключа (<20 — «слишком короткий») как в Soroka.
- Диалог: непустое изменённое поле — сохранить в gigachat.json;
  очищенное (а ключ был в файле) — удалить файл; env-ключ не трогаем
  (он имеет приоритет и показывается пояснением).

## Осталось

- **Soroka переписывает settings.json своей моделью** при изменении
  своих настроек (категории/промпты/подписи) — наши ключи
  `native_theme`/`native_autosync_min` при этом теряются, тема
  откатывается к тёмной. Обратная совместимость по плану обеспечена
  (Soroka наши ключи игнорирует), прямая — ограничена дизайном Soroka.
  Пока правило: тему/трей меняем в одном клиенте; после перехода на
  Native (критерий Фазы 2) вопрос исчезает. Если заведётся —
  восстановление ключей при старте в N10.
- Интервал автопроверки только хранится; таймер, трей, уведомления,
  автозапуск (реестр) — N07.
- autostart в диалоге меняет флаг в settings.json, но сам автозапуск
  (ярлык в автозагрузке/реестр) делает N07 — сейчас флаг просто
  сохраняется (как у полей delayed_actions/idle_enabled, которые
  Native не использует до Фазы 3).
- Далее по Фазе 2: N07 — трей и автопроверка (после живой проверки
  этого среза).
