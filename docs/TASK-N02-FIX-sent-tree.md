# TASK-N02-FIX — дерево папок: «Отправленные» не мигают, колонки по ширине

Дата: 2026-11-22. Версия: 0.3.15. Закрывает замечание из TASK-N02
(«Проверено живьём», 2026-11-18): сразу после отправки письма в дереве
у mail.ru на миг пропадала строка «Отправленные», после перезапуска
возвращалась. Тогда же было записано: «Нужна отдельная проверка
`rebuild_tree` после отправки».

## Постановка

Дерево папок строится из кэша `folders` (`rebuild_tree` → `load_folders`),
а сам кэш при синхронизации INBOX **полностью заменяется** свежим списком
IMAP: `save_sync` → `save_folders` (DELETE всех папок ящика + вставка) →
`prune_folders`, который удаляет письма и тела папок, которых нет в списке.

Два сценария дают «моргание» папки:

1. **Кэш не читается в момент перестройки.** `rebuild_tree` вызывается по
   событию `SyncDone`, при этом рабочий поток уже мог взять блокировку
   SQLite на запись. Старый код в этом случае молча подставлял пустой
   список (`unwrap_or_default` дважды) — ящик на кадр оставался без папок.
2. **Частичный LIST.** Сервер (наблюдение — Mail.ru) иногда отдаёт не весь
   список папок. Полная замена убирала «Отправленные» из дерева и — хуже —
   `prune_folders` стирал кэш писем этой папки. Внешне это и выглядит как
   «папка исчезла, потом вернулась»: строка возвращается следующим удачным
   LIST, а её письма — только после отдельной синхронизации папки.

Оба сценария — в оболочке (`backend.rs`, `ui.rs`), ядро `src/mail/` не
трогается (правило WORKFLOW).

## Решения

### Частичный LIST не стирает кэш папок

Перед полной заменой списка сравниваем свежий список с тем, что уже
в кэше: если свежий непустой список потерял папку, **у которой есть
закэшированные письма** (`folder_total > 0`), считаем его частичным —
обновляем только письма INBOX (`save_folder_sync`), а таблицу `folders`
оставляем как есть (`folders_refreshed = false`, дерево не перестраивается).

Правило вынесено в чистую функцию `list_looks_partial(known, fresh,
has_cache)` и покрыто юнит-тестом.

Компромисс осознанный: папка, действительно удалённая на сервере, но
содержащая письма в кэше, останется в дереве. Потеря писем из-за
неполного LISTа хуже лишней строки; чистится она вручную или будущим
срезом «обновить список папок» с подтверждением.

### Перестройка дерева не показывает ящик пустым

`rebuild_tree` запоминает ключи папок, которые уже были в дереве, и при
ошибке чтения кэша (`Store::open_default` или `load_folders`) показывает
их снова вместо пустого списка. Ошибка остаётся невидимой для владельца —
и это правильно: это транзиентное состояние, а не изменение данных.

### Что не менялось

- Схема БД, `save_sync`/`save_folders`/`prune_folders` ядра — дословно.
- Поведение при реально пустом LIST (защита TASK-026 в ядре) — как было.
- После отправки письма дерево по-прежнему не перестраивается: копия
  в «Отправленные» делается через IMAP APPEND и попадает в кэш при
  следующей синхронизации этой папки.

## Сделано

- [x] `backend.rs`: `list_looks_partial` + защита в ветке INBOX
      (`save_folder_sync` вместо `save_sync`, без prune).
- [x] `ui.rs`: `rebuild_tree` помнит прежние папки и переиспользует их при
      ошибке чтения кэша.
- [x] `ui.rs`: `fit_list_columns` — колонки списка считаются от текущей
      ширины панели (сплиттеры TASK-N04 её меняют). Без этого после
      v0.3.2–0.3.14 у «Даты» оставались фиксированные ширины TASK-N03
      (44+240+460+150 = 894 px) при панели 558 px: «Дата» уезжала за край,
      снизу вечно торчала горизонтальная прокрутка. Теперь «От» 170,
      «Тема» — остаток (мин. 90), «Дата» 120; во время жеста сплиттера
      подгонка не делается (одна — по отпусканию).
- [x] Заголовок окна: «POS Mail» вместо «POS Mail — Фаза 1: почтовый
      каркас» (Фаза 1 закрыта, заголовок путал).
- [x] Юнит-тест на `list_looks_partial` (частичный список, пропавшая
      пустая папка, полный список, пустой ответ сервера).
- [x] Версия 0.3.15 (Cargo.toml + Cargo.lock).

  следующей отправке владельцем (одна отправка между тестовыми ящиками
  по WORKFLOW).

## Осталось

- Если владелец увидит «лишнюю» папку, удалённую на сервере, — завести
  отдельный срез «обновить список папок» с явным подтверждением и
  предупреждением о чистке кэша.
- На узкой панели списка (меньше ~420 px) «От» и «Тема» заметно жмутся;
  если владелец будет часто уводить сплиттер влево — следующий шаг:
  owner-draw строка в две строки (от + тема) вместо двух колонок.
- Живая приёмка Фазы 2 (чек-лист в ROADMAP) — за владельцем.
