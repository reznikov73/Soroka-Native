# TASK-N12 — контакты, часть 1: автодополнение адресов в письме

Дата: 2026-11-22. Версия: 0.3.17. Срез Фазы 3 по ROADMAP: «N12 Контакты —
автодополнение адресов при написании, книга контактов». Здесь сделана
первая половина — автодополнение; книга контактов идёт следующим коммитом
(слой данных под неё в ядре уже готов и покрыт тестами).

## Постановка

Писать адрес руками — самая частая операция в почте. Ядро Soroka уже умеет
всё нужное: `mail::contacts` (модель, CSV/vCard, нормализация) и
`Store::{load_contacts, correspondence_contacts}` (книга + частые
адресаты переписки). Оболочке не хватало только UI: в `compose.rs` не было
ни одной подсказки — ни по вводу, ни по клавиатуре.

Требование: в полях «Кому»/«Копия» при наборе показывать подходящие адреса
и подставлять выбранный в формате `Имя <адрес>, ` — не мешая обычному
набору и не ломая отправку (ядро режет получателей по `,`/`;`).

## Решения

### Данные: один снимок на окно, фильтрация в памяти

В `compose::open` один раз собираются подсказки: вся книга контактов +
до 200 частых адресатов переписки (`correspondence_contacts`, дубликаты по
адресу отбрасываются). Дальше на каждое нажатие — только фильтр в памяти:
правило WORKFLOW «блокирующие операции не в UI-потоке» и требование
мгновенности ввода. Если книга/кэш недоступны — подсказок просто нет,
письмо пишется как раньше.

### Чистая логика — отдельный модуль `src/addr.rs`

Позиции каретки Win32 (`EM_GETSEL`/`EM_SETSEL`) считаются в **единицах
UTF-16**, а строки Rust — UTF-8: на кириллице байтовые смещения дали бы
сдвиг в два раза. Поэтому `token_at` работает с `&[u16]`, и это закреплено
юнит-тестами (кириллица, `;` как разделитель, каретка в середине, пустой
токен после запятой).

`rank` — приоритет: префикс адреса → префикс имени → вхождение, затем
частота переписки, затем адрес (детерминированный порядок). Пустой токен
даёт частые адреса (на будущее — для выпадающего списка по Ctrl+пробел).

`recipient_text` собирает `Имя <адрес>, `; запятые и угловые скобки из имени
вычищаются — иначе `smtp::parse` разрежет получателя на части. Если имени
нет или оно совпадает с адресом — вставляется просто адрес.

### UI: список-оверлей над полем

`LISTBOX` (ID 211) — ребёнок окна письма, создаётся скрытым, ставится под
текущим полем через `SetWindowPos(HWND_TOP)` и показывается
`SW_SHOWNOACTIVATE`. Клик по нему не должен забирать фокус у поля
(`WM_MOUSEACTIVATE → MA_NOACTIVATE`), иначе подсказка закрывается до выбора.

Клавиши в полях «Кому»/«Копия» ловит сабкласс (`GWLP_WNDPROC`, как у поля
поиска в главном окне): ↓/↑ — выбор, Enter/Tab — подставить, Esc — скрыть;
остальное уходит родному `EDIT`.

Вставка — `EM_SETSEL` + `EM_REPLACESEL` (сохраняет undo и не трогает
остальной текст). После вставки подсказка прячется, фокус возвращается в
поле.

Скрытие: пустой токен, нет совпадений, `WM_SIZE`, уход фокуса из поля
(`EN_KILLFOCUS`), успешная вставка.

### Дефект, найденный живой проверкой

Первая версия принимала выбор по `WM_LBUTTONUP`. Клик работал «в пустоту»:
нажатие кнопки забирало фокус у поля, `EN_KILLFOCUS` успевал спрятать и
очистить подсказку, и `WM_LBUTTONUP` приходил уже в пустой список.
Перенесли приём на `WM_LBUTTONDOWN` (до смены фокуса) — клик заработал.
Записано в коде комментарием, чтобы не «оптимизировали» обратно.
